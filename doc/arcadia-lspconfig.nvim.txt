INTRODUCTION                                     *arcadia-lspconfig.nvim*

arcadia-lspconfig.nvim extends native Neovim LSP configurations for Arcadia
tier0 development. The current release supports clangd, Pyright,
BasedPyright, and ya-make-lsp.
It suppresses ty inside Arcadia to prevent a globally enabled ty
server from competing with the Arcadia Python server. Go and other language
modules are planned.

The plugin configures clangd, Pyright, BasedPyright, ty, and ya-make-lsp
during setup. The user explicitly enables clangd and the Python servers with
|vim.lsp.enable()|. ya-make-lsp is enabled automatically.

==============================================================================
REQUIREMENTS                          *arcadia-lspconfig-requirements*

- Neovim 0.11.3 or newer.
- nvim-lspconfig on 'runtimepath'.
- Executable ya and arc commands for Arcadia preparation.
- Node.js and npm for building ya-make-lsp.
- A configured language-server executable for each other enabled server.

The plugin does not install Arcadia tools or general-purpose language servers.
It exports, builds, and updates ya-make-lsp automatically.

==============================================================================
SETUP                                            *arcadia-lspconfig-setup*

Apply user server settings first, call setup once, then enable the servers: >lua

  vim.lsp.config('clangd', {
    capabilities = my_capabilities,
  })

  require('arcadia-lspconfig').setup()
  vim.lsp.enable('clangd')
  vim.lsp.enable('pyright')
<
Default options: >lua

  require('arcadia-lspconfig').setup({
    servers = {
      clangd = { codegen = true },
      pyright = { codegen = true },
      basedpyright = { codegen = true },
      ty = {},
      ['ya-make-lsp'] = {},
    },
    jobs = {
      cancel_on_buff_exit = true,
      timeout_ms = nil,
    },
    log = {
      level = 'warn',
    },
  })
<
                                      *arcadia-lspconfig-servers-clangd*
servers.clangd ~
    Set to false to disable this plugin's clangd integration. Set codegen to
    false to skip the ya make --replace-result stage while continuing to
    generate compile_commands.json. codegen defaults to true.

                                      *arcadia-lspconfig-servers-pyright*
servers.pyright ~
    Set to false to disable this plugin's Pyright integration. Set codegen to
    false to skip the ya make --replace-result stage while continuing to
    generate import paths with ya ide vscode. codegen defaults to true.

                                *arcadia-lspconfig-servers-basedpyright*
servers.basedpyright ~
    Set to false to disable this plugin's BasedPyright integration. Set codegen
    to false to skip the ya make --replace-result stage while continuing to
    generate import paths with ya ide vscode. codegen defaults to true.
    Managing both Python servers is supported; select which one is active with |vim.lsp.enable()|.
    BasedPyright uses nvim-lspconfig's basedpyright configuration and its
    basedpyright-langserver command. Generated import paths are applied as
    basedpyright.analysis.extraPaths.

If both Pyright and BasedPyright are activated for one buffer, both may attach.
Refresh, restart, and health report that the active integration is ambiguous
rather than selecting one silently.

                              *arcadia-lspconfig-servers-yamake*
servers["ya-make-lsp"] ~
    Automatically enabled for files named exactly "ya.make". Set to false to
    disable filetype detection, installation, updates, and LSP activation.

                                           *arcadia-lspconfig-servers-ty*
servers.ty ~
    By default, prevent a globally enabled ty server from starting for buffers
    anywhere below an Arcadia ".arc/HEAD". Existing ty clients are detached
    from matching buffers. Outside Arcadia, normal nvim-lspconfig ty behavior
    is preserved. Set to false to leave ty entirely unmanaged by this plugin.

                         *arcadia-lspconfig-cancel-on-buff-exit*
jobs.cancel_on_buff_exit ~
    Boolean, default true. Remove job interest on |BufDelete| or |BufWipeout|.
    Shared work is cancelled only when no interested buffers remain.

                              *arcadia-lspconfig-timeout-ms*
jobs.timeout_ms ~
    Positive number or nil, default nil. Maximum generation duration in
    milliseconds. Nil means no deadline.

                                *arcadia-lspconfig-log-level*
log.level ~
    One of "debug", "info", "warn", "error", or "off". Default "warn".
    Output is appended below stdpath("state").

Unknown options and invalid values are errors. Repeated setup and calling
vim.lsp.enable() for a managed server before setup are unsupported.

DETECTION AND SERVERS                       *arcadia-lspconfig-clangd*

The Arcadia root is the nearest ancestor containing ".arc/HEAD". The LSP root
is the nearest ancestor containing "ya.make", bounded by the Arcadia root.
Symlinks are not resolved.

Outside such a root, normal nvim-lspconfig clangd behavior is unchanged.

For each LSP root the plugin runs these commands concurrently: >

  cwd: {lsp-root}
  {arcadia-root}/ya dump compile-commands
    --output-file={temporary-file}
    --cmd-build-root={data-dir}/build_root

  cwd: {lsp-root}
  {arcadia-root}/ya make
    --add-result=.hpp
    --add-result=.cpp
    --replace-result
    -o={data-dir}/build_root
<
Valid JSON array output is atomically installed at: >

  stdpath("data")/arcadia-lspconfig/{root-hash}/clangd/compile_commands.json
<
Arcadia clangd is started as: >

  {arcadia-root}/ya tool clangd
<
The cache directory is sent as
"initializationOptions.compilationDatabasePath".

A valid old cache starts clangd immediately before background preparation.
Every successful dump starts or reloads clangd, even when the database is
unchanged. A successful make reloads clangd only if a valid database exists at
that time. Without one, no Arcadia or system clangd starts until the dump
installs it. If make finishes first, its reload is skipped. Failure in either
stage does not cancel the other; existing valid clients and databases remain
active. A failed initial dump leaves clangd stopped.

                                      *arcadia-lspconfig-pyright*
PYRIGHT ~

For a Python buffer, an existing {lsp-root}/pyrightconfig.json is honored and
no preparation is performed. Otherwise the plugin runs these concurrently: >

  cwd: {lsp-root}
  {arcadia-root}/ya ide vscode --py3 --no-pyright-config
    -W=arcadia-pyright -P={revision-project-directory}

  cwd: {lsp-root}
  {arcadia-root}/ya make --add-result=.py --replace-result -R
<
The generated VS Code workspace's python.analysis.extraPaths are validated,
stored under the root-specific Pyright data directory, and merged into native
Pyright settings. A valid cache starts Pyright immediately and refreshes in the
background. Without a cache, startup waits for successful generation. A
successful Python build reloads the server only when configuration is already
available; a build-first reload is skipped. The stages fail independently,
configuration errors take status priority, and failed, cancelled, timed-out,
and stale work cannot replace the last working configuration.

BasedPyright uses the same preparation and pyrightconfig.json behavior. Select
it with servers.basedpyright as described in |arcadia-lspconfig-setup|. Its
cache and status key are "basedpyright", and its client command comes from the
standard nvim-lspconfig basedpyright configuration.

                                      *arcadia-lspconfig-yamake*
YA.MAKE ~

Opening a file named exactly "ya.make" assigns the "yamake" filetype and
enables ya-make-lsp. On first use the plugin runs asynchronously: >

  arc log -n1 trunk --oneline devtools/ide/vscode-yandex-arc/ya-make-lsp
  arc export trunk devtools/ide/vscode-yandex-arc/ya-make-lsp --to {data-dir}
  npm install
  npm run build
<
The npm commands run in the exported directory, never in the Arcadia checkout.
The installation lives at: >

  stdpath("data")/arcadia-lspconfig/ya-make-lsp/
<
Later opens start a valid cached server immediately and check the trunk
revision in the background. A changed revision rebuilds and restarts the
server. A failed update restores the last working installation.

==============================================================================
API                                                *arcadia-lspconfig-api*

setup({options})                        *arcadia-lspconfig.setup()*
    Configure the core and enabled built-in integrations. Must be called once.

status([{bufnr}])                       *arcadia-lspconfig.status()*
    Return nil outside an applicable Arcadia target. Otherwise return a table
    with arcadia_root, lsp_root, and per-server state.

    While both clangd or Python preparation jobs run, stage is "prepare". With
    one job remaining, its specific stage is reported. Configuration-producing
    stage errors take priority over build errors.

statusline([{bufnr}])                   *arcadia-lspconfig.statusline()*
    Return an animated "lsp X" string while preparation is waiting, or an
    empty string otherwise.

refresh([{bufnr}])                      *arcadia-lspconfig.refresh()*
    Restart async preparation for the buffer's root. Return true when
    dispatched, or nil and an error message when not applicable.

Status changes emit the internal |User| event "ArcadiaLspStatusChanged". Its
data is not a public interface.

==============================================================================
COMMANDS                                        *arcadia-lspconfig-commands*

                                              *:LspArcadiaRefresh*
:LspArcadiaRefresh
    Rerun preparation for the current buffer's applicable server.

                                              *:LspArcadiaStatus*
:LspArcadiaStatus
    Display structured status for the current buffer.

                                              *:LspArcadiaRestart*
:LspArcadiaRestart
    Restart the applicable clangd, Pyright, BasedPyright, or ya-make-lsp
    client for the current buffer's Arcadia LSP root. Refuse when its required
    configuration is unavailable.
==============================================================================
HEALTH                                            *arcadia-lspconfig-health*

Run: >

  :checkhealth arcadia-lspconfig
<
The check reports Neovim and nvim-lspconfig compatibility, roots for the file
from which it was invoked, {arcadia-root}/ya, cache validity, server
availability, and current-session workflow state.
